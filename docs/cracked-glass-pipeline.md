# Cracked Glass Anomaly Pipeline — Walkthrough

How the cracked-glass synthetic dataset pipeline works. Every image referenced in this doc is already on disk in the repo — open this file in any Markdown viewer and the visuals render inline.

## Status: diffusion-authored textures are the chosen path

After comparing hand-drawn (PIL `ImageDraw` + Sobel) and diffusion-authored (SDXL line-art + same Sobel) crack textures rendered through OmniGlass on real Innovation Center curtain panels, **the project is going with the diffusion-model approach (variant `v4` and any future SDXL-generated variants) as the canonical crack texture source.**

The rationale — diffusion-authored cracks have richer, more plausible fracture geometry, scale to as many variants as you want without proportional authoring effort, and slot into the existing OmniGlass material pipeline through the same one-line `normal_map_texture` input that the hand-drawn variants use. The v1/v2/v3 PIL textures are kept on disk for historical comparison and for the side-by-side visualizations later in this document, but **they are not part of the production workflow** — new dataset runs should bind v4 (or future v5/v6/... diffusion variants) only.

## What we're trying to do

Train a visual anomaly detector to spot cracked windows in the Innovation Center. The building isn't built yet, so we can't collect real photos. Instead we render synthetic training images inside Isaac Sim where a random subset of glass panels has been given a "cracked" material, and emit segmentation masks as ground-truth labels.

## The four layers

Everything in the pipeline sits in one of four stacked layers. Keep this in mind — every script, file, and tweak in this doc maps to exactly one of them.

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 4 — Dataset script (the runtime loop)                 │
│   for each frame:                                           │
│     1. pick a random 20% of glass panels                    │
│     2. swap their material to a cracked variant             │
│     3. render frame + save segmentation mask                │
└───────────────────────────▲─────────────────────────────────┘
                            │ uses
┌───────────────────────────┴─────────────────────────────────┐
│ Layer 3 — OmniGlass materials (the "cracked look")          │
│   two materials live in the scene at render time:           │
│     • intact baseline (clean OmniGlass)                     │
│     • cracked v4 (and any future v5/v6/... diffusion        │
│       variants — all share this slot)                       │
│   each cracked variant = OmniGlass shader + a normal-map    │
│   PNG wired into its `normal_map_texture` input             │
└───────────────────────────▲─────────────────────────────────┘
                            │ reads
┌───────────────────────────┴─────────────────────────────────┐
│ Layer 2 — Crack normal-map PNGs (the "cracked look" data)   │
│   assets/materials/cracked_glass/crack_normal_vN.png        │
│     • CANONICAL: SDXL line-art prompt → Sobel filter        │
│     • LEGACY:    crack_normal_v{1,2,3}.png — hand-drawn     │
│       PIL.ImageDraw, kept for comparison only               │
└───────────────────────────▲─────────────────────────────────┘
                            │ binds to
┌───────────────────────────┴─────────────────────────────────┐
│ Layer 1 — The building                                      │
│   assets/environments/InnovationCenter/InnovationCenter.usd │
│   1013 glass panel prims, untouched, loaded as a reference  │
└─────────────────────────────────────────────────────────────┘
```

We never modify Layer 1. Everything else is authored fresh at run time.

## Layer 2 — the crack textures

### Canonical: diffusion-authored (v4 and beyond)

Generated by prompting Stable Diffusion XL for a line-art crack pattern and running the output through a Sobel gradient filter (`opacity_to_normal` from `assets/materials/cracked_glass/generate_textures.py`) to turn the grayscale "height map" into an RGB normal map.

**Step 1 — raw SDXL output, prompted for line art:**

![SDXL raw line art](../assets/materials/cracked_glass/crack_raw_v4.png)

Prompt:
> `ink drawing of broken glass cracks, pure black lines on plain white background, technical line art, radial shatter with interconnected secondary fractures, high contrast, detailed fractures, sharp edges, no shading, no color, no gradient, no gray fill, no spider, no insects, no animals`

The prompt is engineered to push SDXL into "ink drawing" territory where brightness cleanly encodes surface height (not lighting). The "no spider" clauses are necessary because "spider-web cracks" causes SDXL to draw actual spiders at many seeds.

**Step 2 — auto-contrast, upscale to 2K, run `opacity_to_normal`:**

![v4 normal map](../assets/materials/cracked_glass/crack_normal_v4.png)

This is the file the OmniGlass shader actually reads. The pale blue-purple tint is a normal map's RGB encoding — flat regions read as `(128, 128, 255)` (pointing straight out of the surface) and crack ridges perturb the X/Y channels into lighter/darker bands.

Run `generate_textures_diffusion.py` with different `--seed` and `--prompt` values to produce v5, v6, v7... — every new variant is a single PNG drop-in, no code changes downstream.

### Tiling toggle

OmniGlass has a `project_uvw` parameter (added to `create_cracked_glass_material()`) that controls whether the crack texture tiles (repeats) across the panel or maps once:

- **Tiling ON** (`project_uvw=False`, default) — the crack pattern repeats across the panel based on its UV coordinates, producing a dense shatter covering the entire surface. This is the look in the v4 render below.
- **Tiling OFF** (`project_uvw=True`) — the crack pattern maps once to the full panel via object-space projection, producing a single impact point with intact areas around it.

Both modes use the same PNG. For dataset variety, randomly toggle between them per panel.

### Legacy reference: hand-drawn (v1, v3)

Kept on disk for historical comparison only. Authored by `assets/materials/cracked_glass/generate_textures.py` using `PIL.ImageDraw.line`. These are **not** part of the production workflow — adding new variants is a 6-second SDXL invocation instead.

## Layer 3 — the material (the integration point)

All four cracked materials are created once at scene load by `create_cracked_glass_materials()` in `sim_utils/glass_anomaly.py`. The function loops over variant names, finds `crack_normal_<v>.png` in the texture folder, and plumbs the PNG into an OmniGlass shader. **The entire integration surface is these three lines of `create_cracked_glass_material()`:**

```python
shader.CreateInput("normal_map_texture", Sdf.ValueTypeNames.Asset).Set(
    Sdf.AssetPath(normal_texture)
)
shader.CreateInput("flip_tangent_v", Sdf.ValueTypeNames.Bool).Set(True)
```

To add a new variant, you drop a PNG into `assets/materials/cracked_glass/` with the right filename and add its suffix to the variants tuple. Nothing else.

## img2img augmentation (optional, for intact frames only)

A separate SDXL pipeline that runs **after** Isaac Sim finishes rendering — feeding each rendered PNG through SDXL img2img with a "photograph of a modern academic building window" prompt to shift the render toward photo-realism. Available via `simulations/dataset/diffusion_augment.py` and `assets/materials/cracked_glass/refine_crack_img2img.py`.

**Do not run on cracked frames** — the diffusion pass rewrites whole-image pixels, so segmentation masks no longer match. Safe only for intact-background frames where there's no per-pixel label to preserve. Kept in the repo for potential future use as a sim-to-real gap closer on the negative class.

## Approaches we experimented with and rejected

During development we also tried:

- **4-map PBR set** (normal + opacity + color + roughness maps) — color map made the biggest visual difference but produced black crack lines instead of realistic white/silver fracture surfaces. Fixing the polarity helped but added complexity without enough payoff over normal-map-only.
- **Geometry-based Voronoi fracture** — procedurally split the glass panel into ~30 shard meshes with random tilts. Produced barely visible results because the tilt angles were too subtle. Real broken glass needs thousands of micro-facets, not 30 puzzle pieces.
- **NVIDIA Blast SDK** — not available in Isaac Sim 5.1 (extension not installed). Would require manual SDK installation.
- **Roughness texture for dirt/fingerprints** — OmniGlass roughness controls frosting (makes glass milky), not surface dirt. Effect was invisible at low values and unrealistic at high values.
- **Texture tiling control** — `project_uvw=True` prevents tiling but the tiled look (pattern repeating) actually produces a more convincing dense shatter. Both modes are now exposed as a toggle.

## Adoption recipe — adding a new diffusion variant `vN`

The whole production workflow for adding a new crack variant is three steps. There is no other path; the hand-drawn workflow has been retired.

1. **Author the texture with SDXL.** Run the generator with whatever variant name + seed + prompt you want:
   ```
   /home/thescript/isaacsim/python.sh \
       assets/materials/cracked_glass/generate_textures_diffusion.py \
       --variant v5 --seed 7
   ```
   Or with a custom prompt for a different fracture style:
   ```
   /home/thescript/isaacsim/python.sh \
       assets/materials/cracked_glass/generate_textures_diffusion.py \
       --variant v6 --seed 13 \
       --prompt "ink drawing of a single bullet hole impact in glass, radial cracks only, pure black on white, no shading"
   ```
   Writes `crack_raw_<v>.png`, `crack_opacity_<v>.png`, and `crack_normal_<v>.png` into `assets/materials/cracked_glass/`. Takes ~6 s per texture on an RTX 5090 once SDXL weights are cached locally (~70 s on a cold cache for the first download).

2. **Register the variant.** Add `"vN"` to the `variants` tuple in `sim_utils/glass_anomaly.py:166` **or** pass `--variants v4,vN` (or any subset of diffusion variants) to `simulations/dataset/cracked_glass_dataset.py`.

3. **Render the dataset.** Run `simulations/dataset/cracked_glass_dataset.py` as usual. OmniGlass discovers the new PNG by filename convention, binds it to randomly selected glass panels alongside the other diffusion variants, and Isaac Sim's RTX path tracer renders each frame normally.

**Isaac Sim never imports `diffusers` and never touches SDXL at render time.** The diffusion model is a one-shot texture-authoring utility that runs once per new variant on the login node (or any machine with a GPU), outputs a PNG, and exits. Isaac Sim is not a runtime dependency of SDXL, and SDXL is not a runtime dependency of Isaac Sim. The two systems communicate through PNG files on disk, nothing else.

**Don't bind v1/v2/v3 in production runs.** The hand-drawn variants are kept only for the comparison images in this doc. Pass `--variants v4` (or a comma-separated list of diffusion variants) explicitly to keep them out of the random pool.

## Known gotchas (unrelated to diffusion, worth fixing before production)

**Gotcha 1 — Silent no-op on pre-bound Mesh prims.** Some glass panels in `InnovationCenter.usd` (frosted spandrels, curtain panels with prior custom bindings) have materials bound directly on their inner `Mesh` prim. Binding at the `Xform` wrapper level with `strongerThanDescendants` does **not** override a sibling binding on a child Mesh. The visual swap silently no-ops. Fix: use `bind_visual_material_deep()` from `simulations/environment/cracked_glass_preview.py` or `cracked_glass_floor4_stream.py` — it walks to the Mesh descendant via `_find_mesh_descendant()`, unbinds the default-purpose binding there, and binds the new material.

**Gotcha 2 — BasicWriter never flushes.** `simulations/dataset/cracked_glass_dataset.py` calls `writer.detach()` before Replicator's async write queue has drained. The result: only `metadata_*.json` files hit disk, zero RGB PNGs. Fix either (a) call `rep.orchestrator.wait_until_complete()` before detach, or (b) replace BasicWriter entirely with direct `rep.AnnotatorRegistry.get_annotator("rgb").get_data()` reads like the preview scripts do.

**Gotcha 3 — GL_4 shadowbox panels slip through the glass filter.** `enumerate_glass_prims()` in `sim_utils/glass_anomaly.py:43` excludes `"GL_3"` shadowbox but not `"GL_4"` (shadowbox with patterned film). GL_4 panels are back-painted opaque architectural cladding, not see-through glass — they shouldn't be in the crackable pool. Fix: add `"GL_4"` to the `exclude_filters` tuple.

None of these block the diffusion-texture work — they apply equally to hand-drawn and diffusion-authored variants.

## Sources & prior art

The approach in this doc was informed by a web-search survey of how people have done cracked glass, material randomization, and anomaly data generation in Isaac Sim, Omniverse, and the broader vision literature. No single source describes this exact pipeline — the closest precedents are cited below, grouped by the layer they informed.

### Layer 3 — OmniGlass material + normal map input
The idea of driving cracks through a bound normal map on an OmniGlass shader comes directly from NVIDIA's material docs, which explicitly call out `normal_map_texture` and recommend DirectX normal orientation (what we use).

- [OmniGlass Material Template — Omniverse Materials and Rendering](https://docs.omniverse.nvidia.com/materials-and-rendering/latest/templates/OmniGlass.html) — shader inputs reference; `normal_map_texture`, `glass_ior`, `thin_walled`, `frosting_roughness`.
- [Materials Best Practices — Omniverse SimReady](https://docs.omniverse.nvidia.com/simready/latest/simready-asset-creation/material-best-practices.html) — recommends OmniPBR + OmniGlass as the canonical pair for simulation use.

### Layer 4 — Replicator material randomization
The per-batch material-swap pattern in `cracked_glass_dataset.py` mirrors NVIDIA's sanctioned "material randomizer" path, though Owen's code drives it through direct `MaterialBindingAPI` calls instead of `rep.randomizer.materials` so the semantic labels stay guaranteed consistent with the binding.

- [Replicator Materials — Omniverse Extensions](https://docs.omniverse.nvidia.com/extensions/latest/ext_replicator/replicator_materials.html) — material library + per-frame bind pattern.
- [Randomizer Examples — Omniverse Extensions](https://docs.omniverse.nvidia.com/extensions/latest/ext_replicator/randomizer_details.html) — `on_frame` trigger + material randomization.
- [Randomization Snippets — Isaac Sim Documentation](https://docs.isaacsim.omniverse.nvidia.com/5.0.0/replicator_tutorials/tutorial_replicator_isaac_randomizers.html) — Isaac Sim-specific randomization helpers.
- [Scene Based Synthetic Dataset Generation — Isaac Sim Documentation](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/replicator_tutorials/tutorial_replicator_scene_based_sdg.html) — end-to-end SDG pipeline with segmentation labels.

### Alternative approaches we considered and rejected
These are the paths the search surfaced that we chose *not* to take, for the reasons documented in the layers above.

- [Blast Destruction — Omniverse Extensions](https://docs.omniverse.nvidia.com/extensions/latest/ext_blast.html) and [Blast SDK Documentation](https://nvidia-omniverse.github.io/PhysX/blast/index.html) — real physics-driven glass fracture via PhysX + Blast. Rejected because it requires per-asset chunk authoring for each of 1013 panels, and the Revit export doesn't ship chunked meshes.
- [Is there a way to achieve projective decal effects in Isaac Sim? — NVIDIA Developer Forums](https://forums.developer.nvidia.com/t/is-there-a-way-to-achieve-projective-decal-effects-in-isaac-sim/338462) — projective-decal "stamp" approach that would sidestep the binding-override bug. Rejected because Isaac Sim's decal support is incomplete and has no clean Python API.

### NVIDIA's own defect detection pipeline validates our approach
The normal-map-based material swap approach is exactly what NVIDIA recommends for synthetic defect data generation. Their blog post describes the same pattern: author defect normal maps, project them onto surfaces, randomize per frame, annotate with Replicator.

- [How to Train a Defect Detection Model Using Synthetic Data with NVIDIA Omniverse Replicator](https://developer.nvidia.com/blog/how-to-train-a-defect-detection-model-using-synthetic-data-with-nvidia-omniverse-replicator/) — uses normal maps projected via a proxy cube to represent surface defects (scratches) on CAD parts. Same integration point as ours: `normal_map_texture` on a material shader.
- [NVIDIA Omniverse Defect Gen Extension (GitHub)](https://github.com/NVIDIA-Omniverse/kit-extension-sample-defectsgen) — the reference extension for defect randomization.

### Diffusion-authored textures (the v4 experiment)
The idea to use SDXL as a texture-authoring tool rather than a runtime augmentation is a synthesis of two precedents: (a) arXiv work showing diffusion models out-generate hand-authored defect textures for classification training, and (b) standard Stable Diffusion img2img / text2img prompt-engineering practice. The specific choice to prompt for line-art (so the output can re-enter the existing Sobel pipeline unchanged) was ours.

- [Enhancing Glass Defect Detection with Diffusion Models: Addressing Imbalanced Datasets in Manufacturing Quality Control — arXiv 2505.03134](https://arxiv.org/html/2505.03134) — uses DDPM-generated synthetic defective glass images to augment training data. Reports +15 pp accuracy on ResNet50V2 (78 → 93%) and recall nearly doubling on EfficientNetB0 (35 → 65%) when synthetic data is mixed in. Different domain (bottles, not architecture) but the core claim — *diffusion beats hand-authored defect textures for classifier training* — transfers.
- [Semantic segmentation with deep learning: detection of cracks at the cut edge of glass — Glass Structures & Engineering (Springer)](https://link.springer.com/article/10.1007/s40940-020-00133-7) — not a synthetic-data paper, but confirms that glass-crack segmentation is a solved problem *given* labeled data — which is exactly what our synthetic pipeline produces.

### What we couldn't find
No tutorial, blog post, GitHub repo, or forum thread describes cracked-glass anomaly generation in Isaac Sim specifically. The approach in this doc — OmniGlass + normal-map swap + semantic labels + optional SDXL texture authoring — appears to be novel in the Isaac Sim ecosystem as of April 2026. If this works at dataset scale it's worth writing up as an Omniverse community post.
